# Governance

Self-Evolution Harness currently uses a maintainer-led model.

## Decisions

- Bug fixes and documentation changes require passing CI and maintainer review.
- Behavior changes require a fixed regression case.
- Active rule or Skill changes must identify evidence, scope, and a retirement
  condition.
- Automatic promotion of feedback into active instructions is out of scope.

## Releases

The primary maintainer verifies tests, rule-health checks, bootstrap behavior,
and release notes before publishing a version.

## Contributions

Issues and pull requests are welcome. Public discussion should contain no
credentials, personal data, or private project history.
